## Confirmed implementation facts

### 1. Five modes exist, but paper and product names differ

The product registry defines `single_shot`, `repeated_single_shot`,
`iterative_no_checklist`, `gym_with_checklist`, and `fixed_transitions` in
[`experiments/modes.py`](../../experiments/modes.py#L24).
`iterative_no_checklist` and `gym_with_checklist` use the same notebook backend
and differ at the episode-mode level only by `checklist_feedback_enabled` in
[`gym/modes.py`](../../gym/modes.py#L15); this equality is asserted in
[`tests/test_episode_modes.py`](../../tests/test_episode_modes.py#L4).

Paper arm mapping:

- A `budget_matched_best_of_n_single_shot` -> current `repeated_single_shot`;
- B `iterative_no_checklist` -> current `iterative_no_checklist`;
- C `gym_with_checklist` -> current `gym_with_checklist`;
- D `fixed_transitions` -> current `fixed_transitions`.

The common runner expands `all` to exactly these five modes and forwards a
shared batch ID, but it does not impose a shared global budget
([`experiments/run.py`](../../experiments/run.py#L123),
[`tests/test_experiments.py`](../../tests/test_experiments.py#L410)).

### 2. `max_tokens` is per call, not per episode

`GymAgent` sends the same `self.max_tokens` on every `client.complete` call and
only accumulates provider-reported totals after the call
([`gym/agent.py`](../../gym/agent.py#L160)). Repeated single-shot and fixed gym do
the same for every attempt/turn
([`experiments/run_multishot.py`](../../experiments/run_multishot.py#L203),
[`experiments/run_fixed.py`](../../experiments/run_fixed.py#L216)). Single-shot
has one call, so its per-call limit is also its generation limit
([`experiments/run_baseline.py`](../../experiments/run_baseline.py#L137)).

`run_gym.py` currently logs both `max_tokens` and `token_budget` with the same
per-call value ([`experiments/run_gym.py`](../../experiments/run_gym.py#L145)).
There is no pre-call remaining-budget check or hard episode-wide token stop.

Post-run self-summaries can make an additional LLM call after the solution is
finalized ([`experiments/run_gym.py`](../../experiments/run_gym.py#L178),
[`experiments/run_fixed.py`](../../experiments/run_fixed.py#L523),
[`experiments/run_baseline.py`](../../experiments/run_baseline.py#L247)). Those
tokens are not added to the main episode totals. Confirmatory configuration must
disable this call or record it separately outside the decision-affecting budget.

### 3. Single-shot controls receive host-side autofit

If baseline prediction fails, the host calls `.fit(...)` and retries before
hidden evaluation ([`experiments/run_baseline.py`](../../experiments/run_baseline.py#L171)).
Repeated single-shot performs the same safety fit before validation-based
selection ([`experiments/run_multishot.py`](../../experiments/run_multishot.py#L241)).
This is evaluator assistance and is not acceptable in the confirmatory A/B/C
configuration unless applied identically and explicitly to every arm. Protocol
V1 chooses no host-side autofit.

### 4. Step, turn, tool, and execution units are not yet a common budget

Notebook actions are accepted before `_consume_step`; notebook-mutating and
execution actions increment `state.step`, while `think`, submit, and tool actions
do not. Non-submit/non-think tools increment `tool_calls_total` separately
([`gym/notebook_env.py`](../../gym/notebook_env.py#L340),
[`gym/notebook_env.py`](../../gym/notebook_env.py#L409)).

`GymAgent` bounds LLM turns by `max_steps * 2 + 5`, not by a global LLM-call
ledger ([`gym/agent.py`](../../gym/agent.py#L153)). Fixed gym has per-stage code
budgets plus a separate turn guard and tool count
([`experiments/run_fixed.py`](../../experiments/run_fixed.py#L183)); the tool-only
guard is tested in [`tests/test_experiments.py`](../../tests/test_experiments.py#L135).

The notebook summary exposes `steps_used`, `cell_executions_total`,
`validation_calls_total`, and `tool_calls_total` as separate values
([`gym/notebook_env.py`](../../gym/notebook_env.py#L1004)). PR 3 must convert these
events into one shared execution policy without erasing the individual counters.

### 5. Tokens, failures, and results are persisted through different paths

- Gym totals are accumulated by `GymAgent` and combined with the environment
  summary ([`gym/agent.py`](../../gym/agent.py#L259)); `run_gym.py` logs selected
  fields and public/private artifact directories to MLflow
  ([`experiments/run_gym.py`](../../experiments/run_gym.py#L210)).
- Single-shot creates a local summary and separately logs MLflow params, metrics,
  code, stdout/stderr, submit error, and JSON summary
  ([`experiments/run_baseline.py`](../../experiments/run_baseline.py#L210)).
- Repeated single-shot records per-attempt usage/errors, aggregates totals, and
  writes `attempt_log.json` plus MLflow metrics
  ([`experiments/run_multishot.py`](../../experiments/run_multishot.py#L267),
  [`experiments/run_multishot.py`](../../experiments/run_multishot.py#L337)).
- Fixed gym stores a stage log with turns/code steps/tool calls/errors and emits
  a separate summary metric mapping
  ([`experiments/run_fixed.py`](../../experiments/run_fixed.py#L311),
  [`experiments/run_fixed.py`](../../experiments/run_fixed.py#L397)).

There is no single atomic `RunManifest`, no per-call usage ledger, no stable
condition ID, and no unified agent-vs-infrastructure failure classifier.

### 6. Hidden score is private, but hidden evaluation is not yet one-shot on failure

On success, notebook submit computes the hidden score host-side, stores it in
`private_summary`, and returns an observation without the score
([`gym/notebook_env.py`](../../gym/notebook_env.py#L789)). Public observations,
events, and summaries remove the score/private fields before writing agent-visible
artifacts ([`gym/notebook_env.py`](../../gym/notebook_env.py#L1376),
[`gym/notebook_env.py`](../../gym/notebook_env.py#L1421)). Tests assert the score is absent
from feedback, notebook output, and public traces while remaining in the private
summary ([`tests/test_notebook_env.py`](../../tests/test_notebook_env.py#L319),
[`tests/test_protocol.py`](../../tests/test_protocol.py#L112)).

However, a hidden-test prediction failure currently permits two repair cycles and
a third hidden attempt before terminal failure
([`gym/notebook_env.py`](../../gym/notebook_env.py#L815)). The behavior is explicitly
tested in [`tests/test_notebook_env.py`](../../tests/test_notebook_env.py#L355).
Although hidden values and the score stay private, failure/non-failure becomes an
adaptive signal and the hidden evaluator is called more than once. Confirmatory
mode must attempt hidden evaluation exactly once and provide no outcome-changing
feedback afterward.

The notebook workspace copies only train/validation CSV files and does not inject
`test_df` ([`gym/notebook_env.py`](../../gym/notebook_env.py#L237),
[`tests/test_notebook_env.py`](../../tests/test_notebook_env.py#L59)). The default
kernel backend is nevertheless local, not an OS sandbox
([`gym/notebook_env.py`](../../gym/notebook_env.py#L42)). Confirmatory runs must use
the Docker isolation path and verify that original dataset paths and host secrets
are inaccessible.

## Documentation drift

1. `docs/PROTOCOL.md` says the system supports four modes and omits a dedicated
   Free Gym mode section, while the registry and runner expose five.
2. `docs/PROJECT.md` and `docs/PROTOCOL.md` describe an eight-item checklist.
   Current code defines 12 mandatory checks in
   [`gym/feedback.py`](../../gym/feedback.py#L112), verified by
   [`tests/test_notebook_checklist.py`](../../tests/test_notebook_checklist.py#L156).
3. `docs/PROTOCOL.md` states a one-time hidden evaluation, while notebook hidden
   failures can currently trigger three attempts.
4. Existing project status and experiment report contain positive pilot findings.
   They are not confirmatory evidence because budgets are unmatched, autofit is
   present, failure accounting is incomplete, and repeats are insufficient.

These documentation issues are recorded here rather than silently changing the
scientific design or runner behavior in PR 1.

## Existing test map and missing acceptance coverage

Existing useful coverage:

- mode ablation: `tests/test_episode_modes.py`;
- per-call token forwarding/aggregation: `tests/test_agent.py`;
- five-mode planning: `tests/test_experiments.py`;
- clean replay, submit gate, hidden-score privacy, step budget, tool privacy:
  `tests/test_notebook_env.py`;
- public observation filtering: `tests/test_protocol.py`;
- legacy submit behavior: `tests/test_env.py`.

Missing before confirmatory execution:

- global raw input/output/reasoning/cached-token enforcement across all calls;
- identical A/B/C call/execution/tool/wall-clock budget tests;
- explicit no-autofit research configuration;
- exactly-one hidden evaluation across success and failure paths;
- unified failure classification and infrastructure replacement behavior;
- stable condition ID, unique run ID, atomic manifest, and resume idempotency;
- local/Docker adversarial tests for inaccessible hidden files and host secrets;
- end-to-end provenance from manifest to final tables/figures.

## Minimal integration map for later PRs

- PR 2: add a thin research manifest/ledger layer around current `run_*` entry
  points and MLflow logging; do not create a second environment framework.
- PR 3: inject one shared episode-budget object into LLM client calls and existing
  executor/kernel actions; add a common submission validator and research-mode
  flags that disable autofit and hidden retries.
- PR 4: plan conditions above `experiments.run` using existing product-mode
  metadata; reuse current runner modules and add resume/duplicate checks around
  them.
- PR 5: read immutable manifests/ledgers as the analysis source of truth; treat
  current MLflow summaries only as compatibility inputs for pilot diagnostics.
